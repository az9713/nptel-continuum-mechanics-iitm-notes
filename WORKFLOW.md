# Lecture-note production workflow

This independent study edition follows the root-level HTML, chapter sidecar,
bundled reader, source-map, executable-code and evidence arrangement used by
the NPTEL Fluid Mechanics and High Performance Scientific Computing projects.
The textbook skills applied are `transcript-grounded-textbook`,
`rigorous-explainer`, and `science-editor`. Planning also uses the STEM textbook
separation of authoring and scientific review. The user authorized autonomous
production and public GitHub publication.

1. Enumerate the supplied playlist and inspect the official course outline.
   Preserve every recording identity and its original position. Resolve course
   attribution, misplaced numbered lessons, duplicate-looking uploads and the
   reverse order of the four live discussion sessions.
2. Acquire recordings locally. Official NPTEL media supports the early lessons;
   YouTube audio supplies the remaining material. Caption requests failed.
   Produce local `faster-whisper small.en` machine transcripts, retaining model,
   decoded-audio duration, media digest and timestamped segments. Quarantine
   truncated transfers and reacquire them before claiming full source access.
3. Read the assigned transcripts sequentially. Build chapter coverage around
   their actual topics and tutorial mechanisms. Do not substitute upload titles
   or official concept lists for source reading. Machine ASR is fallible and
   does not establish board-equation fidelity.
4. Calibrate one pilot chapter against the reference projects. Develop explicit
   objects, hypotheses, derivational steps, recurring cases, runnable checks,
   limits and fully worked exercises. Keep original teaching constructions
   distinct from material directly supported by a recording.
5. Inspect original-author textbooks, official mathematical sources and other
   primary material for the particular claims cited. State convention changes
   and retain unresolved board-input uncertainty instead of inventing values.
6. Apply scientific editing to first drafts. A substantial scientific rewriter
   is an author of the resulting manuscript and does not independently accept
   that same text. Obtain separate reviews, repair findings and bind recorded
   verdicts to the exact authored-body digest. Final review records describe
   what was actually checked and any remaining limits.
7. Assemble the shared reader while preserving chapter bodies. Bundle CSS,
   JavaScript and MathJax for offline reading. Retain chapter navigation, search,
   theme and text controls, expandable solutions, printing and code copying.
8. Execute all authored Python examples in fresh processes and compare actual
   output with the displayed output. Check links, timestamp bounds, source
   coverage, body digests, mathematical rendering and desktop/mobile reader
   behavior. Code execution and browser checks do not substitute for scientific
   or pedagogical review.
9. Audit the public file inventory, rebuild a source-free export, commit and
   push only public deliverables, deploy GitHub Pages and verify served pages.
   Raw recordings, ASR, downloaded references, acquisition logs, caches and
   private editorial material stay in ignored `work/` under the workspace.

The source record, chapter sidecars, editorial summary and validation reports
describe completion and evidence. A page being rendered does not by itself
establish completion. No full audiovisual review, formal proof verification,
material calibration or real-flow validation is implied by the automated checks.
